# D582: The sun's shadows are prepared only for views that draw them

Area: Engine and code · Owner: Tech · By: Agent · Status: Decided

Two pieces of shadow work Bevy 0.20 did every frame and nothing drew are dropped; what is drawn does not change.

- **The late shadow pass without occlusion culling.** `per_view_shadow_pass::<true>` built the late phase's indirect draw parameters for every cascade (a compute pass each, over every phase) and then drew nothing, because `view_shadow_pass` draws a late pass only for a view with `OcclusionCulling`, which no view of ours has. It now returns before opening an encoder when no cascade has occlusion culling, and skips each one that has none, as `late_prepass_build_indirect_parameters` already does for the camera. A patch of `bevy_pbr` 0.20.0 (`patches/bevy_pbr`, D184), marked `Terra's patch (D582)`.
- **Cascades for the interface's camera.** Bevy builds a sun's cascades for every active camera, so the interface's `Camera2d` (`RenderLayers::none()`) had four of its own, each frustum culling every shadow caster each frame, though `prepare_lights` never makes shadow views for a camera whose layers miss the light's. `scene::cascades_for_world_views`, between `UpdateDirectionalLightCascades` and `UpdateLightFrusta`, removes those cameras' cascades by the same rule.

Upstream: Bevy's main still builds the late shadow parameters without the check (2026-10-29). Drop the patch once a release does.

## Why

Perf round 12 counted what the shadow passes draw on `play-walk` (a temporary render-world count of `ViewBinnedRenderPhases<Shadow>`): 11 to 27 multidraw batch sets a cascade, about 77 draws a frame for the four, split by 18 pipelines, 9 material bind groups and 14 mesh slabs; no batchable or unbatchable draws. So the draws were never what `submit_pending_command_buffers` spends: a Tracy capture of the walk showed it at 3.2 ms a frame, 1.2 ms finishing some 33 encoders in parallel (the early shadow encoder the longest at 1.0 ms, but a one-pass tonemapping encoder already 0.26 ms) and 2.0 ms in `queue_submit`. Its cost goes with the number of encoders and passes, not draws, and the late shadow encoder (0.44 ms to finish) did no drawing at all. The interface camera's cascades showed in the main world's count as a second set of four, holding only ground.
