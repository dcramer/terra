# D588: Moves with a start and an end are keyed from a generated pose sheet, on our own skeleton

Area: Art, characters and sound · Owner: Design · By: — · Status: Open

Recommended: moves with a clear start and end that no source does well (blows, a tool's swing, a way of holding) are keyed by an agent against a pose sheet from an image model, as [docs/keyed-moves.md](../keyed-moves.md) says, with no motion generator in between.
- **Where it applies.** Bought clips stay first for long cycles (walking, running, swimming), as D532 has it. This would add a source to D532, which is the developers' to change.
- **What is settled by trying it.** One blow, on a working copy: it starts on the guard exactly, standing feet slip under 1 cm, and it played in the real duel. Its look has not been judged, it has no step forward, and the wrist and shield checks have not run.
- **Nothing is built on this yet.** The spike stays a spike until the developers decide. Every pipeline doc already names it as proposed; keyed-moves.md lists the lines that change either way.

## Why

The developer, 2026-11-01: "I have found using chatgpt to create a pose sheet of the animation sequence, and then I get opus to animate against the pose sheet reasonably effective. lets try this", then "lets start by documenting that process. we're not going to implement it all right now."

Quaternius's and Uthana's blows both failed to mesh with the fight. The same keys always give the same clip here, which answers "what would we do to create a determnistic system". The evidence is in research/2026-11-01-pose-sheet-blow.md.
