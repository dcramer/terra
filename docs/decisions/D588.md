# D588: Moves with a start and an end are keyed from a generated pose sheet, on our own skeleton

Area: Art, characters and sound · Owner: Design · By: Developers · Status: Decided

Moves with a clear start and end that no source does well (blows, a tool's swing, a way of holding), and small loops such as the idle, are keyed by an agent against a pose sheet from an image model, as [docs/keyed-moves.md](../keyed-moves.md) says, with no motion generator in between. Keyed clips go into the game through the character build, their keys the source.
- **Where it applies.** Bought clips stay first for long cycles (walking, running, swimming), as D532 has it; this adds a source to D532.
- **The first in the game** is the standing idle, `Idle_Loop` (2026-11-02), keyed from a sheet drawn from the brief alone, on a neutral start, its empty arms posed from a person at ease.
- **What is not settled by trying.** The step forward in a blow, a whole chain of blows judged together, and keying a clip again per body.

## Why

The developer, 2026-11-01: "I have found using chatgpt to create a pose sheet of the animation sequence, and then I get opus to animate against the pose sheet reasonably effective. lets try this", then "lets start by documenting that process. we're not going to implement it all right now."

The developer, 2026-11-02, shown the in-game film of today's idle beside the keyed one: "if the new idle is that bottom row yeah it looks better"; asked whether keyed pose-sheet clips like it should go into the game from now on: "Yes, keyed clips go in".

Quaternius's and Uthana's blows both failed to mesh with the fight. The same keys always give the same clip here, which answers "what would we do to create a determnistic system". The evidence is in research/2026-11-01-pose-sheet-blow.md.
