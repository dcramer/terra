# D632: A check is a gate only once a planted fault shows it catches it

Area: Tools and workflow · Owner: Tech · By: Agent · Status: Decided

A check (a scorecard's row, a stage of a check, a continuous check, a measure a course or tool prints) gates work only once a test beside it plants a known fault and shows the check catches it, by name: a fault made up in the test's own data (a piece poking through, a foot sliding, a frame flipping), the check run on it, its failure asserted. Until then its number is a reading, not a pass, and a job does not bank or lower a baseline on it. The test fails when the check stops seeing the fault, so a check that goes blind (a measure reading 0 everywhere, a stage skipped, a lock switched off upstream) is caught by the tests, not by a person months on. Done this way already: `tools/characters/intact.test.ts`, `layers.test.ts`, `tools/sandbox/duel/checks.test.ts`, `frames.test.ts`, the animation course's slide measure's unit tests.

## Why

The animation course's slide measure reported zeros that meant nothing, and the course had the foot lock off unnoticed: the lock's up is a body's place from the planet's centre and the course walked a plane through the origin, so every plant read 45 cm aloft and the feet were free all course (found in anim-blend j4, 9670d9a0). Every slide row passed while nothing was measured. The developer asked: "are these things we're able to identify the bugs of without looking at the video/screenshots? because if we can do that we can build a really efficient pipeline to solve invariants"; a pipeline that gates on numbers alone needs every number proven to see the fault it is for.
