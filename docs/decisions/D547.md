# D547: Tunables, named numbers changed while a run goes

Area: Tools and workflow · Owner: Tech · By: Agent · Status: Decided

A value worth trying several of is a **tunable**, as Unreal's console variables are (`TAutoConsoleVariable`, `IConsoleManager`; Epic's "Console Variables in C++"): a static in the module that owns it, with a dotted name from the owner down (`sky.cloud.body_low`), a default, a range and a line of help, read where it is used each time it is needed (`terra_gen::tune`, plain Rust so any crate can own one, D28). The owner's plugin registers its own (`tune::register`) so they are known from the start; a read registers one too. A running sandbox lists, reads, sets and resets them over the remote (`tune.list`, `tune.get`, `tune.set`, `tune.reset`; `node tools/sandbox/remote.ts tune list|get|set|reset`), and `--tune NAME=VALUE` sets one before the run starts. A value outside its range, or a name nothing registered, is refused, and at the start ends the run. Each set is logged (`Tune: NAME was -> now`), and what last set it is kept (default, command line, remote), as Unreal's `ECVF_SetBy*` keeps it. Changes are seen by polling, as Epic recommends over callbacks: read the value, or compare `tune::changes()`. A changed value lasts as long as the run; when one is right, its default changes in the code.

Every build has them, as every build has the remote; a run nobody tunes reads its defaults, an atomic load where a constant was. A value a shader reads goes to it in its uniform each frame. The debug menu (D81) is the next step: a list over the same tunables, so a person and an agent change the same things.

## Why

An A/B was a temporary environment variable read by the code under test, removed before committing (docs/development.md), so each value tried cost a rebuild, a Windows cross-compile and a restart: sky stage 2's round 3 shot heaped cover 0.45, 0.25 and a stretch of the body noise as three separate runs. Unreal's console variables are the industry's answer and the model here; Rust has no code before `main` without `unsafe` (Unreal registers its statics from constructors, and crates like `inventory` do it with link sections, which the workspace forbids), so the owner registers its tunables when its plugin is built. Floats only for now: the values tried so far are all numbers in a range; whole numbers and switches can be added as kinds when one is needed.

Proved by `node tools/sandbox/tunecheck.ts` (under `cargo xtask gpu still`): one running sandbox on the high preset, its clock held, the sky shot, `sky.cloud.heaped_cover` set over the remote, shot again, put back, shot a third time; the sky must change and come back. On the RTX 5090 (2026-10-27): 0.5 to 0.25 changed 50% of the sky band's pixels, and back at 0.5 0.01% still differed.
