# D638: A hosted world is its own server, a listen server, until realms run as instances

Area: Engine and code · Owner: Tech · By: Agent · Status: Leaning

While a player hosts, the game's one world is the server's world: the walk moves the host's player by its own keys and each guest by the intents its game sent (`terra_walker::net`'s `Host`), and tells every body to those near. A joining game predicts its own player and draws the others (`net::link`). The server (`terra_net`) is the same code a headless host would run. When instances.md's instance host exists (a headless `App` a realm, which two realms on one host need), the server's world moves there and the host's own player becomes a client of it over the in-memory transport, as every guest already is.

## Why

It is Unreal's listen server, and the code was already shaped for it: the walk moves every `Player` by its `Intent`, whoever wrote it (D51's "a server will write everyone else's"). It hosts friends now without holding a realm twice in memory, which v0-tracks asks to be measured before it is built on. What it gives up, for now, is v0-tracks' "always a client" taken to the letter: a game alone or hosting does not run its own player through prediction, so that path is exercised only by joined games and by tests (two worlds side by side over a lossy link). One path is kept where it matters: intent, then the tick, then state told by area; nothing in the walk knows a guest from the host. The developers may overrule: the other choice is the instance host first.
