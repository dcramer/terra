# D135: Loading screen

Area: Engine and code · Owner: Tech · By: Agent · Status: Decided

Every build starts on a loading screen that covers the window until the scene is ready: until everything has arrived and a few quiet frames have passed: files systems ask it to wait for (sounds among them), models put in the world, pictures on screen, everything in view the renderer can draw (its mesh, material and textures prepared, whatever the material), shaders compiled, and work a feature reports itself, such as ground still being meshed. Each is a system reporting to one `Progress` in a `Track` set, so a new kind of work is one system, not a change to the screen. The game clock is held meanwhile, and the screen fades as play begins. A scripted run that is not a bench also stands still mid-run, its frames uncounted and its game clock held, while a file asked to be waited for or a model put in the world is still coming and for the quiet frames after (`loading::hold`), so a call or shot on frame N finds what the script put in before it however busy the machine; a hold over 1 s is logged, and one past the scripted cap goes on with a warning. It is one module (`terra_game::loading`) with a `Screen` state (loading, playing), so a later title screen enters loading to get the same screen. Scripted runs count their frames from when loading is done. Something that never comes keeps a player out at most a minute; a scripted run waits up to ten, saying every 15 s past the first minute what in view it still waits for, by name, so a film never starts with pieces missing. Pictures read on the CPU only (building's texture arrays) load from their own asset source, `cpu://`, never as the same asset as a picture a material draws.

## Why

The developers found the start odd: grey ground and the HUD while models loaded and shaders compiled, with things appearing one by one. A screen over the start, with progress, is what shipped games do; waiting on shader compilation as well as files is what removes the grey ground. Not a loading screen within a world or between worlds, which D4 and D72 rule out. Counting script frames from the end of loading makes scripts independent of how long loading took on a machine.
