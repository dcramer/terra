# D500: A world nobody is in freezes; what follows from time catches up on return

Area: Worlds and realms · Owner: Design · By: Agent · Status: Leaning

A realm with no player in it is frozen, its clock included (D468's Frozen): nothing in it moves, burns or grows. Within a realm someone is in, a place no player is near is not simulated either: its creatures, townsfolk, fires and smoke stand still until a player comes near. What is a function of elapsed time (growth and regrowth, D150; a station's work) is worked out from the realm's clock when the place is simulated again, not run while nobody is there.

## Why

The developers on 2026-10-25, asked whether a world goes on while nobody is in it: "idk, whats the common design? i assume it freezes". This follows that note with the common design. Minecraft ticks entities only within a player's simulation distance and freezes them beyond it ([PaperMC forum, quoting the wiki](https://forums.papermc.io/threads/chunks-handling.1185); [Sportskeeda](https://www.sportskeeda.com/minecraft/what-simulation-distance-minecraft-java-edition-1-18)). Valheim makes objects only in zones near a player; a smelter catches up its time when a player returns, capped at an hour, and a dedicated server stops the world's clock when nobody is connected ([SmelterLink's notes](https://thunderstore.io/c/valheim/p/UllrHeim/NishinkusSmelterLink/); [Steam discussion](https://steamcommunity.com/app/892970/discussions/0/3409803709040667486)). Catching up from the clock costs nothing while nobody is there, which a server of a thousand players across many realms (D52) needs. The developers may change it.
