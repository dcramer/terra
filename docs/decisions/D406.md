# D406: The slow sweeps run on every core, optimised, and an asset is read only by the crates that read it

Area: Tools and workflow · Owner: Tech · By: Agent · Status: Decided

A test that sweeps many independent cases runs them on every core (`terra_gen::par::map`, in the items' order, a panic re-raised with its message), and `terra_build` is optimised in the dev profile as `terra_gen` is; building's key, roof and face sweeps are the first. An asset is read by the crates on Bevy, which load any of it, and its building, life and climate data by the crates that read them too (`READ_BY` in `xtask/src/scope.rs`, amending D398's "`assets/` is read by every crate"); a test fails when a crate names a path under `assets/` not listed. The check names any test over 120 s (`SLOW_TEST_SECS`), timed from libtest's own 60 s warning, so a sweep grown slow shows in the scheduled full check. Everything the check runs runs at `nice 10`, so renders, films and a game started beside it stay responsive. The shared seed builds the sandbox in release too, which every render, shot, film and bench runs, so a fresh worktree links it rather than building Bevy optimised alone.

None is sampled: the slow sweeps run whole, its tests stage under 2 minutes rather than 22. Since 2026-10-19 they run in the full check, scheduled on main, and no hook runs a test (D37).

## Measured

On the 24-core machine with other agents building and rendering (load average in brackets):

| | Before | After |
|---|---|---|
| A push changing terra_build (one comment) | 26m 06s, its tests 22m 34s [30-41] | 3m 24s, its tests 1m 49s, the artifacts 55 s [15-32]; its commit 19.6 s |
| A push changing one asset (a comment in `drift.ron`) | 21m 29s, every crate tested [16-50] | 35 s, terra_world, terra_game and terra_sandbox tested [11-28] |
| A push over everything (a manifest changed; this change's own) | 24m 21s (D398's) [30-135] | 5m 41s, its tests 3m 49s [20-64] |
| A fresh worktree's first `cargo build --release -p terra_sandbox` after the seed | 4m 24s, 2.7 GB | 2m 11s, our 11 crates alone, 0.24 GB its own and 2.3 GB linked [15 at the start] |
| The key sweep (`sections::tests::keys`) | 1228 s | 76 s [21] (152 s on every core unoptimised) |
| The roof sweep (`no_part_of_a_roof_lies_over_itself`) | 124 s [40] | 27 s [10] (48 s optimised alone) |
| The face sweep (`no_two_faces_…`) | 181 s [140] | 9 s [10] (92 s optimised alone) |
| Compiling terra_build whole, its lib and its tests | 29 s and 71 s | 48 s and 81 s; a small edit 2-6 s either way |

The seed's release build of the sandbox adds 3 minutes to a seed rebuilt for new manifests, once for every worktree. The tests stage was the push: one binary's slowest test bounds it, and the key sweep alone was 20 minutes on one core. Now the building push's tests are bound by the other sections sweeps, 77 to 118 s each, the next to spread over the cores, and its artifacts ratchet is a quarter of it; no test passed 120 s.

## Why

The developers, 2026-10-17: "precommit checks shouldnt take more than like a few tens of seconds, rest should be bigger checks". After D398 a commit met that, but a push touching building still took 26 minutes and one touching any asset 21, every crate tested; the agents waiting on them were most of a session's wall time. A test spread over the cores answers the same question as before, all of it, so nothing is skipped to be quick.
