# D627: Token consumption is a constraint of how we work

Area: Tools and workflow · Owner: Tech · By: Agent · Status: Decided

Every agent knows its context and spend, and every bound is held by a tool, not by good intent:

- **Context bound.** A job stops at the bound its brief names; any other session, a coordinator included, at 150k. The context hook (`tools/token-stats/context.mjs --hook`, D390) reads a job's bound from its brief and warns once at 80% (finish and land the step, start nothing new), then says STOP at the bound and at each 20k past it: commit what is checked, write the handoff, report and end. A coordinator at its bound writes a lead handoff (`~/.cache/terra-handoff/<topic>-lead.md`) and asks the developer to `/clear` and continue from it.
- **A coordinator holds no file dumps.** It reads briefs, reports and handoffs; finding goes to `finder`, running to `runner`, building to a `job` (D391, D538).
- **Reads and outputs are budgeted.** Read by grep or line range, never a whole large file; long output to a file, its tail read. The docs every agent reads have size budgets the docs check holds (`node tools/docs/docs.ts`): a component doc says where it stands and what is next (its history is git's and `docs/decisions-log.md`'s), a skill is a short core linking its detail, a tool's README what to run with each script's entry in a reference beside it (`scripts.md`, `made-clips.md`). A reference is read by an entry's grep or a section, never whole, each entry one line or section so a grep returns it whole; it is capped at 40 KB, past which it is split by stage. The four docs over budget when this was decided were trimmed (pipeline-docs j1, j2), and none is held over.
- **No idle past the cache.** A subagent whose wait would pass an hour (D397) hands off instead of waiting: the next job starts from the handoff.
- **Hooks are quiet.** A hook that adds to every turn adds only what is new (the desk reminder at most once an hour, D422).
- **Effort by the work.** A mechanical job (a re-run, a bake, a sweep, a refresh of a status page's stale rows, each judged by a status page or scorecard that says whether it worked) runs at medium effort; design, debugging and judging stay at the default.
- **A job reports its numbers.** Its handoff gives `node tools/token-stats/job.mjs --job '<topic> j<n>'`'s row: context at first edit, summed input, output, peak.

## Why

The measured pipeline (research/2026-11-05-agent-pipeline-tokens.md): an average job took 144 turns and 21M summed input, with 111k of context before its first edit (our code 50k, its own output 70k, docs 29k, search 25k, a 25k prefix of which 7.7k unrelated plugins). Jobs briefed to 150k ended at 215 to 257k, since the nudge fired only at 200k; a coordinator reached 260k, reread every turn; one subagent waited 11 hours and wrote 115k again. The developer, 2026-11-05: "the efficiency is CRITICAL here so we can design characters that are great. people online have figured this out with agents, you must too", "Nothing else that's highly wasteful in general", and "Clean it up and cement policy here around being aware of token consumption."
