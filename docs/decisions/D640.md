# D640: The instance host is a switch over realm servers: each realm a headless `App` with its own server, a connection routed to one

Area: Engine and code · Owner: Tech · By: Agent · Status: Decided

**Each realm instance is whole in itself**: a headless `App` (its `World`, `FixedMain`, each layer's plugin less drawing) holding its own `terra_walker::net::Host`, so its own `terra_net::Server`, tick count and records. **The instance host** (`terra_walker::net::instance`, `Instances`) owns the carrier (UDP, the in-memory transport, or both) behind a **switch** (`terra_net::transport::switch`): a peer belongs to one realm's lane; before the tick the switch hands each lane what arrived for its peers, the Active realms tick at once on the task pool (each touching only its own lane), and after it the switch sends what each lane gathered. A new connection goes to the home realm; a crossing hands the peer to another realm's lane, which greets it as a new arrival (D639's greet, ready, welcome), the client holding its clock while it makes the land. A Frozen realm is not ticked, so its tick and clock stop (D500). **A hand-on on the wire**, built in `terra_net`: a second challenge mid-session resets the client whole (`Event::Handed`) and it says its hello again; a server's challenges and every state packet either way begin with the server's epoch (`Config::epoch`, the realm's number), checked before acknowledgements are touched, so a copy still in flight to or from the realm left is dropped unread and counted (`strays`); and a server ignores well-formed words that come before the hello (the old session's, still on their way; the ordered lane lets none follow it). The game's side is built too: the link holds, walking nothing, until the game has made the land of the realm it was greeted to (`Link::crossing`, `Link::arrived`; `title::joining`). What hands a player on in play (the portal, D470) is not: only a script does.

**Layers move in one at a time.** `Instances` is given the plugins to add (D198: the walker's own first: the ground, the mover, the walk, the host's half of `net`); a layer whose rules run without drawing adds its plugin. **The game's own hosting stays the listen server until a realm instance holds every solid the walk asks about** (trees and rocks, props, bases) and the creatures: before that a host walked by an instance would be pulled through its own walls. Until then the instance host serves scripted runs and soaks with no window (`cargo run -p terra_walker --example nethost`), and D638's deletion of the listen path waits on that parity, not on the instance host existing.

## Why

One server over rooms (`terra_net`'s rooms, built) was the other way: it keeps one tick and one session, but every realm's telling goes through one server serially, and a realm cannot move to another process, which instances.md names as the reason an instance is the unit (D52). A server a realm is how shipped worlds of many zones are built (a gateway routing connections to zone servers), parallel in everything, and it leaves `Host`, `hear` and `tell` as they are, tested. Trees are stood by the camera's streaming with their drawn models (`terra_world::woods::near`), props and bases do not cross yet: found reading for this decision, which is why the game's hosting cannot move yet. The developers: "for decisions use state of the art approaches that are practical for our game's ambition".
