# D183: Builds in worktrees

Area: Tools and workflow · Owner: Tech · By: Agent · Status: Decided

A new worktree's `target/` is seeded before it first builds from the shared seed: a build of origin/main kept for this alone in `.git/terra-seed/` (not a worktree, so the worktree cleanup leaves it; it sweeps itself of what its builds no longer use whenever it is built, D259), built by the cargo commands agents run (the check's, each member's tests alone as `cargo test -p <member>` builds them, since Cargo resolves dependencies' features for the packages chosen, the sandbox's, and under WSL the Windows sandbox in debug and release). `cargo xtask seed` fetches, builds the seed again when origin/main's manifests (`Cargo.toml`s, `Cargo.lock`, toolchain, cargo config) differ from those it was built from, holding a lock so sessions starting together wait for one build, then links from it. It is routine: a Claude Code hook runs it when a session or subagent starts in a worktree with no build, and from the main checkout at most every 15 minutes. Each run fast-forwards the main checkout to origin/main when it is on `main` with no changes and nothing unpushed, never stashing, resetting or rebasing it, and says what is in the way otherwise. `--refresh` runs the seed's builds again, and `cargo xtask doctor` reports the seed's and the main checkout's state. Only dependencies are seeded, never our own crates, and it follows Cargo's locks, so a build started meanwhile waits for it. Their `.rlib`, `.rmeta` and `.so` files are hard links to the seed's, since rustc and the linker only ever replace those with new files; fingerprints, dep-info and build-script output, which are rewritten in place, are copied. A path dependency outside the workspace (the patched Bevy crates in `patches/`) is judged by Cargo by its files' times, so seeding gives each of its files whose bytes match the seed's the seed's time, and leaves one that differs to be rebuilt. No compiler cache and no build folder shared between checkouts.

## Why

Every new worktree built all of Bevy, 5 to 7 minutes; seeded, it builds in about a minute. sccache missed every crate built on a build script, since those embed the worktree's path, so it saved nothing. A shared `build.build-dir` let one worktree take another's edited code, since Cargo judges our crates fresh by file times. Copied, the seed was 10.5 GB of real disk per worktree on ext4, which cannot clone files, and ten subagents at once held over 130 GB (2026-10-13); linked, it is 0.2 GB. Measured in [research/worktree-builds.md](../../research/worktree-builds.md). The seed was the main checkout's own build until 2026-10-16, which was often missing or behind main's dependencies, so new worktrees built from nothing (10 to 20 minutes); the developers: "you need to make sure (1) is like a normal part of our operations", and "part of the routine somehow is gonna be keeping main updated, and shared build etc". The seed's first build took 17 minutes.
