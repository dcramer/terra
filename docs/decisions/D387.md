# D387: A Makefile as the front door

Area: Tools and workflow · Owner: Tech · By: Developers · Status: Decided

A `Makefile` at the root gets a new machine ready (`make setup`: rustup and the pinned compiler, Xcode's command line tools or Bevy's Linux libraries, the hooks, a first build, `cargo xtask doctor`) and names the everyday tasks (`make play`, `fresh`, `yard`, `update`, `check` and so on), each one line calling `cargo xtask` or `cargo`. It holds no logic of its own beyond installing what Cargo cannot: tasks stay in `xtask` (D121).

## Why

The developers on 2026-10-16: "can we setup a makefile that makes it easy to get the environment up and running? because im not a cargo expert and e.g. you cant even just 'cargo install' or anything simple". `make` is on every machine we use, and `make setup` then `make play` is the shortest start.
