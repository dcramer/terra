# D413: Landing takes turns: a push's check runs again only what a rebase changed, and at most two build and test at once

Area: Tools and workflow · Owner: Tech · By: — · Status: Superseded by D37

Was: a push's check that passed stamped its tree (`xtask/src/stamp.rs`), so after `git pull --rebase` the next ran only what the rebase changed; a check that built or tested took one of two machine-wide slots (`xtask/src/slot.rs`); and landing took turns, as a merge queue does (the `land` task, `xtask/src/land.rs`, `~/.cache/terra/land.lock`), the hook's `check --pushing` taking the same turn.

## Why

Made when a push's check took most of an hour under load and lost the race for main to whoever pushed meanwhile, so the same check ran again and again. Superseded on 2026-10-19, when the developers re-scoped the gate (D37): "remove land, slots, stamp and tiers". The full check now runs in GitHub Actions on a schedule and the push's hook only formats and lints, in seconds, so losing the race for main costs seconds, and the machinery cost more than it saved: one landing through it took 64 minutes, 28 of them waiting for a slot.
