# D525: Binary assets live in Git LFS, from now on

Area: Tools and workflow · Owner: Tech · By: Developers · Status: Decided

Every binary asset and piece of source art is stored in Git LFS from the cut-over commit on; the history before it is not rewritten, so the whole files already in it stay there. The repository owner's GitHub account (dcramer/terra) sets the LFS storage and bandwidth budget. That much is the developers'; how it is done is the agent's (changeable with a reason):

- **What**: by extension, every file of a binary type however small (`.gitattributes`: models `.glb .bin .fbx .blend .vox`; images and textures `.png .jpg .jpeg .webp .tga .tif .tiff .psd .kra .exr .hdr .ktx2 .dds`; motion capture `.bvh`; sound, video and fonts `.ogg .wav .flac .mp3 .mp4 .webm .mov .ttf .otf .woff2`), so the rule is the name alone and a hook can check it. At the cut-over that was 754 files, 1.19 GB (1.11 GiB). Text stays in git, large or not (the generated `.rs` and `.ron` tables are diffed and reviewed). Bevy's crates under `patches/` keep their few binaries in git: bevy_pbr compiles its `.ktx2` files in with `include_bytes!`, which must never read a pointer.
- **Hooks** (D37): `tools/git/lfs.ts`, which needs no git-lfs, refuses a commit (staged files) or a push (each commit not yet on origin) that writes such a file whole rather than as a pointer, since an agent without git-lfs would otherwise put the binary in the history for good. The pre-push hook then uploads the objects with `git lfs pre-push`, after the checks; the filter is set with `git lfs install --skip-repo`, since our hooks are `.githooks`.
- **Render worker** (D445): a job's or update's commit reaches the box by `git push` over ssh, which carries pointers only; the client then rsyncs the LFS objects the commit points to into the box clone's store (`.git/lfs/objects`), only those it lacks, and fetches from origin only those this machine lacks too. The box has its own git-lfs (the pinned official release, checksum checked, `bootstrap.sh`) set as its clone's filter, so its checkouts smudge from that store and never download. `--doctor` reports both.
- **Worktrees and the seed** (D183) share the main checkout's store (`.git/lfs`, git's common folder): a checkout smudges from it, downloading only what no checkout here fetched before. `cargo xtask doctor` reports git-lfs and its filter. The size lint measures Rust sources only and is untouched.

## Why

Greg, 2026-10-26: "we also will wanna go through with doing LFS for all assets"; asked how, he chose from now on, with no history rewrite, and the repository owner's account to set the LFS budget. The repository carried 1.2 GB of models and images in git, every version of each kept in every clone. The attribute lines are those `git lfs track` writes (`filter=lfs diff=lfs merge=lfs -text`), as GitHub's guide has them; by extension rather than by size so the rule never depends on a file's history. GitHub meters LFS bandwidth per download, so the worker and the seed, which check out every commit, take objects from this machine's store, never from GitHub.
