# D407: How the crates are cut

Area: Engine and code · Owner: Tech · By: Developers · Status: Decided

`terra_build` (71k lines) and `terra_game` (60k) are cut into domain crates of some 6 to 17k lines, each one domain with a clear owner of its types, along the lines of the [research](../../research/2026-10-18-crate-layout.md). Building's plain Rust becomes the rules, the layout (where pieces go, which a server needs) and the drawing (which it does not), and settlements become `terra_town`. The game becomes the base on screen, the walker, survival, and above it creatures, townsfolk and building play side by side, under a thin `terra_game`. The world stops depending on building (`Walker` into `terra_core`, the start fitted to a plot of its own). Cargo then holds D198's layer rule, since a crate cannot name one above it, and D28's list of crates on Bevy grows with the game's. Seams are cut inside a crate first, with a test holding each line, and a crate moves only once nothing crosses its line the wrong way; each step lands alone and is measured with `cargo build --timings`. The crates take the research's names, and `terra_life` merges into `terra_town` (the developers, 2026-10-19). Building's fixtures are `terra_build_scenes`, over the rules, the layout, the drawing and the town; the example bases built from the rules alone (the example cabin and bench village, the castle, the burg, the junctions) stay in `terra_build`, since a crate's tests can lay only what is below it. So building's crates leave `terra_build` from the top: the scenes, then the drawing (`terra_build_mesh`), then `village` into `terra_town`, then the layout (`terra_build_layout`).

## Why

The developers asked for obvious speedups and named "segmenting the game modules so they look like a larger-scale Rust/Bevy game" as part of it, then, of the recommendation, "do it", and "its not just about build times tho to be clear, part of this is to reduce complexity of modules, improve scopiing, etc" (2026-10-18). On D198 they asked for modules "pluggable and mostly large enough chunks i.e. not 'microservices'": domain crates, not a crate per feature. A crate is the unit Rust scopes by: what it does not depend on it cannot reach, and an agent reads one by its README without the rest. Build time follows: a touch-only dev rebuild of the sandbox pays `terra_build` 29 s, `terra_world` 23 s and `terra_game` 16 s in series, and release builds, which every shot, film and bench runs, are not incremental. Veloren's server compiles without its graphical client, and matklad's measure of a crate is what it does not depend on.
