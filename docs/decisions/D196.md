# D196: Best-in-class prior art, from any engine

Area: Engine and code · Owner: Tech · By: Developers · Status: Decided

For anything we build, it is always fine to look for the best implementation there is, in any engine, game, tool or paper, and rewrite it for ours; whatever engine it runs on, we can rewrite it for Bevy. Where Bevy falls short, this is the answer, not an invention of our own or a change of engine. Ported from its source where the licence lets an MIT project take the code (MIT, BSD, Apache, zlib: Godot, Voxel Tools, O3DE, Jolt), and from its documentation, papers and talks where it does not (Unreal, anything GPL). How deep into Bevy the change goes is D184; a paid one is D526.

## Why

Said by the developers on 2026-10-12, after asking whether Haxe and Heaps would spare us the character and terrain problems: "if bevy isnt good at something, our best solution is to find a version of it in an engine that is, and reimplement it, ideally from source if we can". Those problems were mostly not Bevy's (stale clips, a rig whose twist bones moved no skin, a crate's seam bug), and a smaller engine has the same gaps. A shipped implementation's source carries the edge cases a description leaves out.

Widened by the developers on 2026-10-26: "its always ok to look for best-in-class prior art, even if its from a different engine, as we can always rewrite it for our engine".
