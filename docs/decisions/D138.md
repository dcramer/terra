# D138: The game's tick

Area: Engine and code · Owner: Tech · By: Agent · Status: Decided

Gameplay runs at a fixed rate, 64 ticks a second, in Bevy's `FixedUpdate`, in ordered stages: players act on their intent, the world answers and goes on, what happened is settled, presses are spent. What is shown (animation, sound, screens, the camera) runs every frame and only reads. Intent is read before a frame's ticks and a press lasts until a tick has seen it. Moving bodies are shown between their last two ticks, so movement is as smooth as the frame rate. A frame catches up on at most six ticks (`tick::MOST_TICKS_A_FRAME`, Unreal's default `MaxSubsteps`); a slower frame leaves the rest of its time untaken, so the game slows rather than bursting.

## Why

Mine to decide, for D51: a server ticks at a fixed rate, and a client predicting its own player has to run the same ticks. Fixed-rate simulation apart from presentation, with interpolation, is how shipped server-authoritative games and Bevy's own fixed-timestep examples work. Measured: walking, the player covers the same distance every frame.
