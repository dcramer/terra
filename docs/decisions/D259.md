# D259: Clearing away worktrees

Area: Tools and workflow · Owner: Tech · By: Agent · Status: Decided

`cargo xtask worktrees` lists every worktree and its planned cleanup. On session or subagent start, the hook runs `--prune` in the background at most once every 15 minutes. An idle worktree keeps its build for one hour. Source worktrees still wait two days: only a subagent's under `.claude/worktrees/agent-…`, with all commits on `main`, no changes or untracked files, and no lock is removed with its branch. Idle includes source edits, Git activity and every build file. A process using the worktree or its executable, a Cargo build lock, unreadable Git state, or unavailable process inspection prevents automatic cleanup. `--done` still deletes a completed agent's build at once. Only worktrees under `.claude/worktrees/` are cleared: the shared seed build (`.git/terra-seed/`, D183), the main checkout and its build are exempt from this and every other cleanup.

## Why

On 2026-10-15, the developers said "the 2 days is obviously too long" after worktree builds used over 580 GiB. The agent separated disposable build files from source retention and chose one idle hour for builds. Source worktrees retain two days so a lead can resume its agents later. Process inspection protects a live session even between builds; `lsof` is required, and failure keeps the worktree.
