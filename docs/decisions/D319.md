# D319: Benchmarks have the GPU to themselves

Area: Tools and workflow · Owner: Tech · By: Developers · Status: Decided

Every unattended GPU run an agent starts (a shot, a film, a sheet, a bake, a benchmark) goes through the scheduler, `cargo xtask gpu <class> -- <command>` ([tools/gpu](../../tools/gpu/README.md)): it starts runs side by side while the card's memory fits each class's estimate (learned from the peaks it measures, free memory read live), short classes first and waiting raising a job's place, and a benchmark only on an empty card, nothing beside it. Under it the game's own turn stays: a benchmark takes an exclusive advisory lock on `~/.cache/terra/gpu.lock` (`TERRA_GPU_LOCK` to move it), every other unattended run the same lock shared (`gpu_turn`); the scheduler holds it for its job, and a run started without the scheduler takes it itself with one of a few slots (`TERRA_GPU_SLOTS`, three by default). A run someone plays never waits. `flock ~/.cache/terra/gpu.queue` is a legacy path the scheduler counts as a running film, not a lock it takes. A run is stopped as stalled only when its whole process tree has made no progress for its class's limit: no output (its own or a `--watch` file), its CPU time not growing (/proc, summed over its processes) and none of them busy on the card (`nvidia-smi pmon`). A silent run that works is alive; one that is hung uses nothing, and the limit stays the ceiling for it.

## Why

At first every unattended run took the GPU in turn, after several at once froze a developer's game and spoiled every benchmark. The developers, 2026-10-15: "yesterdays gpu preempting was costly and caused us slowness, it only matters to do it when we measure perf." Rounds then went back to one serial queue (`flock gpu.queue`), and the 2026-10-19 audit ([research](../../research/2026-10-19-agent-throughput.md)) found agents spent "62% of their hours waiting on GPU runs" while the GPU "was busy about 27% of the time": a 30 s still waited 10 to 40 minutes behind films. What runs out is the card's 10 GB, so runs are admitted by memory, as a batch scheduler admits jobs by their resource requests. Stalls were first judged by output alone, and on 2026-10-21 that stopped a lake film at frame 146 of 600 after a 1h16m wait, its script writing to its own log, and mountain sheets and castle stills the same way: hours lost to working runs, while agents forgot `--watch` and `--stall 40`.
