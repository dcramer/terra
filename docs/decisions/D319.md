# D319: Benchmarks have the GPU to themselves

Area: Tools and workflow · Owner: Tech · By: Developers · Status: Decided

A benchmark waits for an exclusive advisory lock on one file, `~/.cache/terra/gpu.lock` (`TERRA_GPU_LOCK` to move it), held until it exits; every other unattended run (a shot, a film, a sheet, a run driven in the background) takes the same lock shared and one of a few slots (`TERRA_GPU_SLOTS`, three by default, files beside the lock), so up to three run side by side and the rest wait, and none while a benchmark holds the lock (`gpu_turn`). A run someone plays never waits. A measurement of one's own takes `flock ~/.cache/terra/gpu.lock <command>`.

## Why

At first every unattended run took the GPU in turn, after several at once froze a developer's game and spoiled every benchmark. The developers, 2026-10-15: "yesterdays gpu preempting was costly and caused us slowness, it only matters to do it when we measure perf."
