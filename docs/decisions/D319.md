# D319: Benchmarks have the GPU to themselves

Area: Tools and workflow · Owner: Tech · By: Developers · Status: Decided

Only a benchmark needs the GPU alone. Every unattended GPU run an agent starts (a shot, a film, a sheet, a bake, a benchmark) goes through one thin wrapper, `cargo xtask gpu <class> -- <command>` ([tools/gpu](../../tools/gpu/README.md)), which runs it at once: there is no queue, no memory admission and no ordering. A shot, sheet, film or bake holds the game's turn, an advisory lock on `~/.cache/terra/gpu.lock` (`TERRA_GPU_LOCK` to move it), shared for its life, and so runs beside any others. A benchmark takes the lock alone: it leaves a want-file beside the lock while it waits for the shared runs to end and while it runs, and new shared runs wait while one is there, so a benchmark is never starved. Under the wrapper the game finds the turn held and waits for nothing; a run started without it takes the lock itself (`gpu_turn`), with one of a few slots (`TERRA_GPU_SLOTS`, three by default). A run someone plays never waits. A run is stopped as stalled only when, holding the lock, its whole process tree has made no progress for its class's limit: no output (its own or a `--watch` file), its CPU time not growing (/proc, summed over its processes) and none of them busy on the card (`nvidia-smi pmon`). A silent run that works is alive; one that is hung uses nothing, and the limit stays the ceiling for it.

## Why

At first every unattended run took the GPU in turn, after several at once froze a developer's game and spoiled every benchmark. The developers, 2026-10-15: "yesterdays gpu preempting was costly and caused us slowness, it only matters to do it when we measure perf." Rounds then went back to one serial queue (`flock gpu.queue`), and the 2026-10-19 audit ([research](../../research/2026-10-19-agent-throughput.md)) found agents spent "62% of their hours waiting on GPU runs" while the GPU "was busy about 27% of the time". A scheduler that admitted runs by their memory estimate followed, but on a 10 GB card with estimates near 7 GB it ran nearly everything one at a time again, and films waited 2 to 4 hours. The developers, 2026-10-23: "we dont need scheduler, i told you long time ago to remove it." Stalls were first judged by output alone, and on 2026-10-21 that stopped a lake film at frame 146 of 600, its script writing to its own log: hours lost to working runs.
