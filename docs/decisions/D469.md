# D469: World content is scoped by default, and a module never names its instance

Area: Engine and code · Owner: Tech · By: Agent · Status: Leaning

On the client, what belongs to the current world is found by rule ([instances.md](../instances.md#compartmentalization-in-the-ecs-d469)):

- **Entities.** `WorldScoped` is a required component of `Transform`, registered first in the shell (`App::register_required_components`), so every placed thing is the world's at spawn. `Global` opts out (its hook removes `WorldScoped`), on the few roots that outlive a world: the player's body and the camera. Leaving despawns every `WorldScoped` root with its descendants (`World::despawn_all_where`, as Bevy's `DespawnOnExit`); children of a `Global` root stay. A world entity with no `Transform` adds `WorldScoped` itself.
- **Resources.** A module declares the ones its world owns (`app.world_resource::<R>()`); leaving removes them. It builds them from `WorldSpec` in `OnEnter(InWorld)`, never in `Startup`, and its systems run only while they exist (D198).
- **Components on global entities** (sky, haze, grading on the camera) are declared with `app.world_component::<C>()` and removed from every entity on leaving.
- **Caches that outlive a world hold `AssetId`s**, not strong handles.
- **States.** `Travel` is `Away`, `Entering`, `Playing` or `Leaving`; the computed state `InWorld` spans entering and playing, so content spawned while entering is scoped too. The first world of a run is entered like any other, by the `Cross` command; a run starts `Away`, since Bevy runs a state's first `OnEnter` before `PreStartup`.
- **The census** counts entities by archetype and scope, assets by type, resources present and GPU memory by label, read as `world.census` through the remote probe; a round trip that changes it is a leak.

## Why

As Unreal's seamless travel, belonging to the world is the default and persisting is opt-in, so a new module is scoped without knowing instances exist and the few global roots are the ones that must say so. A required component costs no extra archetype move, unlike an observer inserting a marker after spawn; registering it after a `Transform` exists fails at start (`ArchetypeExists`), loudly. Removing declared resources rather than every resource keeps Bevy's and the app's own. Dropping a resource drops its tasks, cancelling meshing in flight. Rejected: a world-scoped marker on each module's root components by hand (`#[require]`), which every module would have to remember.
