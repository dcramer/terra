# D398: The gates scale with the change

Area: Tools and workflow · Owner: Tech · By: Developers · Status: Decided

The check before a commit is linters and at most fast unit tests, budgeted at a few tens of seconds on a built tree (30 s, `COMMIT_BUDGET_SECS`; it says when it is over); every big suite runs before a push, and later on CI. Each gate runs only the stages that can see what the change touches (`xtask/src/scope.rs`), and `--all` runs a gate over everything.

**What a change is.** Before a commit, the tracked files that differ from HEAD; before a push, everything that differs from the merge-base of HEAD with origin/main. A file in a crate's folder is that crate (xtask's for the tasks); `assets/` is read by every crate; the files outside the crates that a crate reads are listed in `READ_BY` (the demos' `places.ts`, the voxel contract's JSON, `art/`), and a test fails when a crate names a repository path outside its folder that is not listed. `tools/<dir>`, the docs, the agents' folders and the top-level notes are seen by their own checks. A change to the workspace's manifest, its lock, the compiler, cargo's or clippy's settings or the hooks, or a file the rules cannot place, runs everything.

**Before a commit** (`cargo xtask check --quick`): formatting when Rust changed, the size and one-definition gates, the docs check and the shared crates' repeatability always; clippy and the tests (`--tests`: no examples' builds, no doc tests) of the changed crates only, without `SLOW_TESTS`; the tests of the tools changed; the Bevy rule when a manifest changed.

**Before a push** (`cargo xtask check`): clippy and every test, the slow ones too, of the changed crates, the crates reading a changed file, and every crate depending on any of them (cargo's own inverted tree, dev dependencies included), with xtask, whose tests read every Rust source, whenever Rust changed; all the tools' tests; the kit checker and the artifacts and fuzz ratchets when building or a crate under it, the assets or the tasks changed; the foliage check when the assets or the textures tool changed; the Blender scripts' check when a Python script or the Blender tool changed.

**What is no longer run, and why that is safe.** A commit no longer lints or tests the crates depending on the one changed, runs no slow test, kit, foliage or other tool's check: the push before the change reaches anyone runs them, over the same tree. A push no longer tests a crate that neither changed nor depends on what changed: its code and everything it reads are as on origin/main, which passed the same gate when it was pushed. The rule is conservative where it cannot tell: anything unplaced runs everything.

`SLOW_TESTS` holds every test over five seconds on the loaded machine (38, from 4): the drawing sweeps, the town and village laid whole, the land's place finders.

## Measured

On the 24-core machine with four other agents building and rendering (load average 60 to 95), on a built tree:

| | Before | After |
|---|---|---|
| A commit of docs only | 3m 12s (the whole quick check) | |
| A commit changing one crate (terra_build) | 3m 12s | |
| A push of a docs change | 18 to 40 min (the full check) | |

The quick check's tests were 2m 52s of the 3m 12s, all of it running tests, none compiling: the test binaries run one after another, terra_build's for 142 s (a few tests of minutes each) and terra_land's for 72 s (its site searches). A worktree or main checkout behind what it last built adds the compile on top, about 4 minutes for every workspace crate under this load: the evidence's 9-minute tests stage.

## Why

The developers, 2026-10-17: "i think there were fixes to making pre commit checks faster. they are too expensive now", and "theres a difference between big suites of tests performance tests rendering pipelines etc. vs like linters and at most units. precommit checks shouldnt take more than like a few to few tens of seconds, rest should be bigger checks. we can later on run on ci". A commit touching only `.claude/settings.json`, two docs and a README had run the whole quick check in 11 minutes, and pushes 18 to 40; agents waiting on the hooks were a large share of what the token audit found spent.
