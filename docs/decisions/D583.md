# D583: A multidrawn batch set's bin buffers are written only when they change

Area: Engine and code · Owner: Tech · By: Agent · Status: Decided

Bevy 0.20's `write_binned_instance_buffers` wrote each multidrawn batch set's three bin buffers (its binned mesh instances, bin metadata and bin-index map) to the GPU every frame, a `Queue::write_buffer` each, changed or not. Each such write makes a staging buffer, copies into it, records a copy and frees the staging buffer once the GPU is done, so the cost goes with the number of writes, not their size. The batch set now keeps a `dirty` flag, set by every method that changes those buffers (`insert`, `remove`, `allocate_bin_metadata`, `remove_bin_if_empty`), and the three are written only when it is set; the GPU only reads them, so the copy it has stays right. A patch of `bevy_render` 0.20.0 (`patches/bevy_render`, D184), marked `Terra's patch (D583)`; Bevy's own property test of the batch set checks after every insert and remove that a buffer whose bytes changed is marked.

Upstream: not yet offered (2026-10-29).

## Why

Perf round 13 broke `queue_submit` down in a Tracy capture of `play-walk` with wgpu-core's own spans let through: of some 380 `Queue::write_buffer` calls a frame, 229 came from `write_binned_instance_buffers<Shadow>` (three for each of the cascades' ~77 batch sets) and 88 from the main and prepass phases, and freeing their staging buffers (`triage_submissions`) took 1.1 ms of `submit_pending_command_buffers`'s 3.1. The command buffers themselves (32 a frame, almost all real passes) cost about 30 µs each to submit. Bench `play-walk` on the RTX 5090: median 10.32 to 9.16 ms, 99th percentile 15.86 to 13.38, frames over the budget 4.8% to 1.0%; the render world's work 8.42 to 6.67 ms a frame, the GPU's 3.62 unchanged.
