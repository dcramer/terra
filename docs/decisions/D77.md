# D77: Logs and frame-time readout

Area: Tools and workflow · Owner: Tech · By: Developers · Status: Decided

Every build has a frame-time readout on screen at all times, judged against the D25 budget, with a graph of the last 240 frames' work, a bar a frame against the budget line, and more on F3: a graph each for game CPU, render CPU and GPU, frame times, render time per pass, entities, memory. A frame's work is the longest of game CPU, render CPU and GPU, since they run side by side; with vsync on, time between frames only reflects the screen. The log keeps engine chatter out and records a summary of frame times once a minute and a warning when frames stutter (over twice the budget), so every session leaves a record of how it ran.

## Why

Asked for by the developers so performance budgets can be kept. Built in `terra_world` (`debug.rs`); `--clean` leaves the readout off pictures. The graph added on 2026-10-13: a red line at 77 fps was hard to read, since its colour came from a figure it did not show. Budgets for parts of a frame (terrain, plants, players) come when those parts exist. See [development.md](../development.md#logs-and-the-frame-time-readout).
