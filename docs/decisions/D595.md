# D595: The volumetric fog's point and spot light march is skipped where no cluster along the ray holds one

Area: Engine and code · Owner: Tech · By: Agent · Status: Decided

Bevy 0.20's `volumetric_fog.wesl` marches every fog pixel twice: once for each volumetric directional light, sampling its shadow map, and once more for the clustered point and spot lights, which looks up the cluster and samples the density texture at every step even where the clusters hold no light. When a directional light's march has run, the second march is now taken only if a cluster the ray passes through holds a point or spot light; otherwise the pixel returns what the first march gave. A pixel's clusters along its ray are one run of indices (its depth slices, `fragment_cluster_index`), so the test walks that run once. A patch of `bevy_pbr` 0.20.0 (`patches/bevy_pbr`, D184), marked `Terra's patch (D595)`.

Upstream: not yet offered.

## Why

Where no cluster holds a light, every step of the second march adds nothing to the colour and works the background's transmittance out step for step as the directional march did (same density, same steps, same early stop), so the result is the same to the bit; the march is pure cost. A fire's glow (D496) marches with no directional light, so it keeps the second march as before, as does any ray through a lit cluster (a lantern, a fire at night). Measured on the worker's 4090 at the lake in play, 1901x1550 (play-lake-fps j6): volumetric_lighting 1.44 ms falls to 1.09 (two runs a side in one job), the frame's median 11.54 to 11.22 ms. The lake's three views at 17 h move 0.00-0.09% of pixels against the unpatched build, within a build's own noise.
