# D133: Repository layout

Area: Tools and workflow · Owner: Tech · By: Developers · Status: Decided

Each kind of thing has one home. Runtime assets the game loads in `assets/` at the root; the source art the pipeline makes them from in `art/`; engine-free rules in their crates (D28); the game's Bevy code in `terra_game`; testbeds and engine-side developer tools in `terra_sandbox`, on top of the game; everything that runs outside the game, the asset pipeline included, in `tools/<name>/`; repository tasks in `xtask`. A spike holds only throwaway work, answers one question, and is deleted once its research note is written; anything something else depends on moves out of it first. Where a new thing goes is in [research/repo-layout.md](../../research/repo-layout.md#proposed-layout).

## Why

Things began as spikes or experiments, became load-bearing and were never moved: the game grew inside the sandbox, the character pipeline inside spikes, and its source art in an ignored scratch folder of one worktree. The layout follows Rust workspaces (rust-analyzer, Bevy), multiplayer games in Rust (Veloren) and the industry's split of source art from runtime assets. Agreed by the developers on 2026-10-12, who also had the Godot builds deleted (D12).
