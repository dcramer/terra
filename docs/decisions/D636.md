# D636: The wire is our own bit packer with a total reader, and `terra_net` knows no game type

Area: Engine and code · Owner: Tech · By: Agent · Status: Decided

`terra_net` is plain Rust, generic over what the rules crates send: each defines its own parts, intents and operations and encodes them through `terra_net::wire`, a bit packer ported from Fiedler's (his yojimbo, BSD-3): ranged integers, quantised floats, varints. The reader is total: any bytes give a value or an error, never a panic or an allocation past a stated cap. Acknowledgements for the unreliable lane are ours (a sequence, an ack and a 32-packet field a packet), so they do not depend on the transport. The protocol's version is a hash of the wire schema and the game's data fingerprint, checked on connect.

## Why

Network input is untrusted (D51), so the reader's totality must be ours to test; quantising to a range we choose is beyond a general serialiser's model; and `bincode`, the usual choice, is unmaintained since 2025-12 ([research/2026-11-06-netcode.md](../../research/2026-11-06-netcode.md)). A net crate that knows no game type keeps D28 and D198: a layer's wire types are defined by the layer, and a bot or load-test client needs no Bevy.
