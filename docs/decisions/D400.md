# D400: Agents' tasks are bounded

Area: Tools and workflow · Owner: Tech · By: Developers · Status: Decided

Every agent's brief says when it stops: a score bar, a number of rounds or two rounds without a gain, a clock time, and a context of about 250k at most (D390). An agent does one unit of work, writes a handoff file and ends; the next round is a fresh agent started from the handoff. It waits by starting a long run in the background and taking the completion notice, never by a polling loop, with one wait per thing. Agents it starts get the same bounds, one helper at a time.

## Why

On 2026-10-17 lead agents had run 6 to 17 hours to 250-970 calls each, at median contexts of 400-660k; a token audit of all sessions found 1,425 hand-written polling loops and 11 waits stuck 30-106 minutes behind a GPU hold, several duplicates, about 50 background tasks at once. The developer: "we should make it some sort of guideline for tasks that they arent meant to run inifinyely".
