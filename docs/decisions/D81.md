# D81: Debug menu

Area: Tools and workflow · Owner: Tech · By: Developers · Status: Decided

An in-game debug menu, switched on by a flag at launch and opened with the backtick key, for debugging tasks such as warping the player. Absent unless the flag is given. Its first page is every live tunable (D547): a searchable list grouped by prefix, a slider within each one's range, its help line and a reset; warp, give, time of day and weather come next.

How it is built (technical, by the agent): the flag is `--debug-menu`, and the menu is drawn with egui (`bevy_egui`, already in every build for the F1 inspector), as Dear ImGui debug windows are in shipped engines; each page is a tab its owning plugin adds. Bevy UI is the game's own interface, but it has no slider, text field or collapsing group to hand, each of which the menu would have to build first; egui has them all. A script's pointer (`sandbox.click`) reaches egui, so an agent drives the menu as a person does. egui is drawn by a camera of its own, last, over the finished picture at the screen's resolution (`crates/terra_world/src/overlay.rs`), as engines draw debug UI over the final frame: on the main camera it was drawn into the world's picture, which the low preset renders at 0.6 of the screen and stretches (D239), so the menu and inspector came out soft there. The game's Bevy UI is drawn by that camera too, being the last on the screen.

## Why

Asked for by the developers on 2026-10-10 (the key was "maybe"). Should share its commands with QA for agents (D69), so anything the menu does an agent can do. Its first page, on the review desk on 2026-10-27, asked whether the menu should show a slider for every live tunable: the developers picked "Sliders for every tunable" (recommended: the same list the agents drive over `r tune`, so nothing is built twice). See [development.md](../development.md#debug-menu).
