# D623: A world's land is generated off the main thread, behind the loading screen

Area: Engine and code · Owner: Tech · By: Agent · Status: Decided

Serves D135, D469 and D13. Entering a world first passes through a state of its own, `Travel::Generating`, before `Travel::Entering` builds it. Meanwhile the world's land (`planet::entering::made_land`: the start search, working out the land round the start, choosing where to stand, the first town) is made on a thread of its own. The loading screen is drawn and says which part is being made. The world is entered in the frame the land comes back, and its `OnEnter(InWorld)` build runs as before on the land made. The game's background pools are not used, because they keep `terra_gen::par::map` to one thread (`terra_world::threads`) and the land spreads over every core. A run with no loading screen, which is a layer's test, makes the land as the world is entered, in the same frame, as before.

While generating, a system that reads what the world has not made yet (`Res<Planet>`, `Res<Start>`, any world resource) is skipped, not run. This is done through the world's fallback error handler, which is swapped for one that drops `SystemParamValidationError` while the land is being made and put back on entering. Other errors are handled as Bevy's default handles them. The cut needs no change to the 87 systems that read the planet. Other work a module makes for the world can join it by name (`instance::Generating::begin` and `done`).

The loading screen's give-up timer (60 s for a player) does not count the generating frames, because the land always comes. `Loaded in` is still timed by the wall clock from the start.

Rejected:
- Gating every world system on the planet with `run_if(resource_exists::<Planet>)` or Bevy's `If<Res<_>>`. That is Bevy's usual way and the most explicit, but it means touching some 90 systems in 6 crates, and every new one must remember it. Any system that forgets panics only on the frames of a load.
- Not running `Update` and the schedules after it while generating. The loading screen's own systems, the interface's layout and the shaders' tracking live there too.
- Making the land in pieces over frames on the main thread. Each part (the look round alone is 5-11 s over 14-21 cores) is one parallel sweep, and splitting it would hold every frame.

## Why

The brief for core-game-world j3, from the town j4 timing on the worker: "The whole land setup runs before the first frame, with no loading screen: start search, working out the land round the start, the first-town search. That's 8–23 s. Shipped games run world generation as a background task behind a loading screen with progress."
