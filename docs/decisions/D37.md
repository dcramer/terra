# D37: Repository tooling

Area: Tools and workflow · Owner: Tech · By: Agent · Status: Decided

One Cargo workspace at the root with a pinned compiler. `cargo xtask check` is the gate for every change. Git runs its quick form before each commit (`--quick`: formatting, lints, the tests but the slow sweeps named in `SLOW_TESTS`, the kit, foliage and docs checks and the dependency rule) and the full check before each push (adding the slow sweeps, the artifacts ratchet and the Blender scripts' check), from `.githooks`, switched on by any `cargo xtask` task; `--no-verify` is not used. `cargo xtask check` with no flag is the full check. Both are scoped to what the change touches, the quick one held to a few tens of seconds, and `--all` runs either over everything (D398). CI can run it on Linux, macOS and Windows, but only when started by hand: it is off until we need it. `cargo xtask doctor` checks a machine, and `cargo xtask win` runs a Windows build on the GPU from WSL. `AGENTS.md` holds the instructions for every coding agent; `CLAUDE.md` only points to it. Agent skills live in `.agents/skills`, with `.claude/skills` linking to it, so every coding agent finds them.

## Why

Two developers on different platforms, and agents writing the code, need one command that says whether a change is acceptable. Tasks are written in Rust so they run the same everywhere. CI turned off on 2026-10-12: "im not sure CI is really adding much value rn btw, worth disabling it til we need it". Split into quick and full on 2026-10-16, with the developers' agreement, since the full check ran several minutes on every commit, much of it in three sweeps over every case of building's drawing.
