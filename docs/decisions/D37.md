# D37: Repository tooling

Area: Tools and workflow · Owner: Tech · By: Developers · Status: Decided

One Cargo workspace at the root with a pinned compiler. `cargo xtask check` is the gate for every change, in three tiers, each scoped to what the change touches (D398). Git runs two from `.githooks`, switched on by any `cargo xtask` task, and `--no-verify` is not used: the quick check before each commit (`--quick`: on the staged files, formatting, the code-health gates, the baselines, clippy and the tests of the crates changed but the slow ones named in `SLOW_TESTS`, the tools' tests changed, the docs check and the dependency rule, in a few tens of seconds), and the push's check before each push (no flag: the same over everything that differs from the merge-base with origin/main, with the crates reading a changed file). The full check (`--full`) adds the tests of every crate depending on them, the slow tests, every tool's tests, and the kit, foliage, artifacts, fuzz and Blender checks when what they read changed; `--all` runs it over everything.

GitHub Actions runs `cargo xtask check --all` on every push to main, on Linux with no GPU and no Blender (those stages skip and say why; `.github/workflows/main.yml`). When it fails, the run bisects the failing stage alone between the last passing run's commit on main and the failing one (`cargo xtask nightly --bisect`, the probe D411's run bisects with: a commit that does not build is skipped, the tip's baselines laid over each commit's), sets a failing commit status on the first commit where it fails, and opens or comments on the issue "main fails the full check", which the next passing run closes. It reverts nothing: a commit that others built on is undone by a person or the agent fixing it. Whoever broke main fixes it before more lands on what it touches. The same workflow started by hand with a stage and a commit bisects a branch without the check, to try it.

`cargo xtask nightly` (D411) stays as it is, run continuously on one machine of ours by the CI agent (`cargo xtask ci --watch`, [ci-agent.md](../ci-agent.md)), which files its failures as issues labelled `ci-agent`: it runs the one stage GitHub's check does not, the artifacts ratchet over every scene rather than the quick set, and it is still the one place a baseline is lowered (D414), since GitHub's run only reads the repository and pushes nothing. Both bisect with the same probe. `ci.yml` runs the full check on Linux, macOS and Windows, and a compile check for the Windows target we cross-compile from WSL, only when started by hand. `cargo xtask doctor` checks a machine, and `cargo xtask win` runs a Windows build on the GPU from WSL. `AGENTS.md` holds the instructions for every coding agent; `CLAUDE.md` only points to it. Agent skills live in `.agents/skills`, with `.claude/skills` linking to it, so every coding agent finds them.

## Why

Two developers on different platforms, and agents writing the code, need one command that says whether a change is acceptable. Tasks are written in Rust so they run the same everywhere. CI turned off on 2026-10-12: "im not sure CI is really adding much value rn btw, worth disabling it til we need it". Split into quick and full on 2026-10-16, with the developers' agreement, since the full check ran several minutes on every commit, much of it in three sweeps over every case of building's drawing.

Moved to CI on 2026-10-18 by the developers: "Yes: keep a fast pre-push check and run the full check in GitHub Actions on every push to main, with bisect on failure. Update D37 accordingly." Under load the push's check took most of an hour (D413), most of it the dependents' tests, the slow sweeps and building's ratchets, and every agent waited on it before landing. On 2026-10-19, before this change, the push's check took 30m 03s over a one-line change to terra_build (its tests 20m 20s, three slow sweeps over 7 minutes each; kits 55 s, artifacts 4m 38s, fuzz 2m 09s) and 12m 30s over one to xtask alone (artifacts 6m 23s, fuzz 4m 01s), on a built tree; the fast push runs none of those stages. What a push no longer runs is still run on every push to main, within the hour, and the commit that broke it is named, so a fault reaches main but not past the next run; the repository is public, so Linux runner minutes are free.
