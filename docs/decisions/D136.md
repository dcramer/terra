# D136: Kinds of thing as data

Area: Engine and code · Owner: Tech · By: Agent · Status: Decided

Kinds of item, recipe, station and creature are entries in RON files in `assets/data/`, one file per feature, read by the plugin that owns it. Code asks what a kind can do (whether a tool builds, what it cuts, what it shoots) and never names one. The files are read when the game starts, each into a registry: a resource the systems that need it read (`terra_world::data` for the world's, `play::registries` for the game's), with kinds known by their place in it and names resolved to them once, as the file is read. A mistake in a file stops the game, naming the file. Which kinds a server runs on is the server's to send (D51). Every kind is read this way: items, stations, recipes, what the hammer builds, creatures, what grows and what the ground gives.

## Why

Mine to decide, to keep D127: the kinds were Rust enums with a `match` per property, so adding one meant code in several files. RON because the game already uses it for saves. Registries rather than files built in, so the content can be swapped as a whole (by a world's theme, by a server, by a file edited while the game runs), which is how data-driven games keep their definitions.
