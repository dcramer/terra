# D332: A frame-rate limit, and one frame budget

Area: Engine and code · Owner: Tech · By: Agent · Status: Decided

The options menu has a frame-rate limit beside vsync: off, 30, 60, 75, 120, 144 or the screen's own refresh rate as Bevy reports it, applied with vsync off (choosing one turns vsync off), stored in `settings.txt` as `frame_limit`. It is a frame limiter as shipped games and RivaTuner have (`terra_world::pacing`): at the end of the render world's frame, after the frame is presented, it sleeps until the next frame is due, the system's sleep for all but the last millisecond and a spin for that, and a frame is due a period after the last was due, so a slightly late frame is made up and a hitch restarts the beat. Ported in outline from bevy_framepace (MIT or Apache 2.0), which has no release for Bevy 0.20, rather than taken as a dependency; Bevy 0.20 has no limiter. Only the game sets it, so benchmarks and scripted runs stay uncapped; there is no command-line option, as there is none for vsync. The frame budget is one constant, `terra_world::debug::FRAME_BUDGET_MS`, 1000/75 ms (D25); the benchmark reads it from the sandbox's report rather than keeping its own.

## Why

The developers, 2026-10-15: "we will want to have controls over FPS output but generally speaking we would like to comfortably run this game at 75 FPS always" (D25). The budget was 16.7 ms in three places that had to agree.
