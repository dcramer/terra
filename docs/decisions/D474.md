# D474: Dungeon cells are dressed by wave function collapse over a theme's socketed modules

Area: Worlds and realms · Owner: Tech · By: Agent · Status: Leaning

Every placed cell takes a module from its theme's set, turned to any facing ([dungeons.md](../dungeons.md)). A module's four sides each take sockets: `open`, `wall`, `door`, `stair`, `rubble`, `water`. A side placement made a wall, door or stair's way must take that socket; an open side, into the same room or corridor, must share an interior socket (open, rubble or water) with the module across it. Water modules' open sides take only water and no dry module takes water, so water fills a whole room or corridor run or none of it. The cells placement fixes (the goal's dais, each key room's altar, lever or brazier, the rest room's fire, every stair cell) take their module in whatever facing fits.

The solver is the simple tiled model: collapse the cell with the fewest variants left, by weight, and propagate arc consistency over open sides; a contradiction, or a dressing whose blocking modules cut a cell off from the entrance, starts again from a derived seed, up to 8 times; then the theme's plain floors, which always solve. Themes are data, a file each in `assets/data/dungeons/` (D136): their goal, size, levels, keys, building kinds, features, bestiary, loot and modules. The sheet (`cargo run -p terra_dungeon --bin dungeons`, D71) measures every theme over a thousand seeds and draws maps of the first.

## Why

Socketed tiles are how shipped games dress a grid by WFC (Townscaper, Bad North, Gumin's simple tiled model) and they keep a theme a list of modules, not code. Holding placement's cells as given is what keeps the mission's promises: WFC only decorates, never moves a door. Retries and a fallback that always solves keep generation total, and the sheet's solve rate says when a theme's modules fight each other.
