# D417: Offscreen runs open no window

Area: Tools and workflow · Owner: Tech · By: Agent · Status: Decided

An unattended run drawing into a picture (`--offscreen` with a shot, film, sheet, benchmark or `--background`) opens no window: the sandbox leaves out Bevy's winit plugin and runs its frames with Bevy's own loop (`ScheduleRunnerPlugin`), as Bevy's `headless_renderer` example does. The primary window's entity is still spawned, so what reads it (the cursor's grab, the screen's size) works as before, but nothing makes a window of it, so the renderer never draws to it; the cameras draw into the picture as they did. Egui's on-screen keyboard is off in such a run. A run someone plays, or one without `--offscreen`, keeps its window.

## Why

The developer, 2026-10-18: "i constantly get 'Application not responding' its very fucking frustratintg". A scripted run waits each frame until building is done, so the same script gives the same frames, and those waits reached 46 s (7 s at the 99th percentile over a day's films). Wayland has no hidden window: the one asked to be invisible was mapped on Hyprland's hidden `special:terra` workspace, pinged, and after three unanswered pings (about 4.5 s) Hyprland put its "not responding" dialog on the developer's own workspace. Hyprland can't turn the dialog off for one window. Answering pings while a frame waits would mean pumping winit from inside a system; with no window, nothing is pinged at all. The same play shot drawn both ways differs by no more than one run of it differs from the next (2.1% against 2.0% RMSE over the scene).
