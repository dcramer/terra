# D411: A full run on main, by hand, lowers the baselines and bisects what breaks

Area: Tools and workflow · Owner: Tech · By: Agent · Status: Decided

`cargo xtask nightly` (`xtask/src/nightly.rs`) runs what no hook runs whole, on origin/main, in a worktree of its own (`.git/terra-nightly/src`, seeded, D183): clippy and every test of the workspace, the slow ones too, the kit checker, the artifacts ratchet quick and over every scene, fuzz over seeds 0 to 200, the size ratchet, and the docs check after rendering their indexes (D409). It is run by hand, for now, not on a schedule: the developers, on 2026-10-18, "maybe we dont need this right now" of starting it every few hours (a session hook on a developer's machine, or a CI cron as is usual). Whoever runs it starts it from any checkout; a lock keeps it to one at a time, and a commit already run is not run again. Until it is scheduled, baselines fall only when someone runs it, which leaves the ratchets slack, never wrong.

**It pushes to main on its own.** That is what the developers asked for: lowering only in an automated job on main (D414). When every stage passes it is the one place a baseline is lowered: what fell (and an index that was stale) is committed alone, "Baselines lowered to main's at <commit>", and pushed with the hooks, `TERRA_BASELINE_JOB=1` letting the baselines stage pass the lowering. Those files are a class of their own in the check's scoping (`xtask/src/scope.rs`), not a change to `terra_build` or xtask: they run only the cheap stages, since the baselines stage holds their rules, a rise only loosens a ratchet and only this run lowers one, having measured it. So its push is checked in seconds and lands before main moves. If main moved anyway, it carries over only what its measurement still holds for (an artifacts or fuzz file when nothing building's check reads changed and the file itself did not; a size entry when its file did not change; the indexes rendered again), three times at most, then leaves it to the next run.

When a stage fails it lowers nothing and `git bisect run`s between the last passing run's commit and the tip, the probe being that stage's own command held to the tip's baselines over each commit's, skipping (125) a commit where it does not build. `.git/terra-nightly/report.txt` says what happened; on a failure its first block is the stages failed, the first bad commit with its subject, and the failing lines.

`TERRA_NIGHTLY=0` in the environment makes it do nothing, for when it is scheduled.

## Why

The full artifacts ratchet and the full fuzz run were run by no hook: the push runs the quick artifacts set, and only when building changed, so wood and stone went back to 42 mesh faults after reaching zero, found by a review rather than a gate. And D414 left lowering to a scheduled job that did not yet exist, while agents hand-lowered baselines and raced each other onto main. The industry's answer is a scheduled build of main with automatic bisection (Chromium's and LLVM's bots, `git bisect run`). Scheduling it is left until it is needed; when it is, a CI cron (D37) is the usual place, not a developer's machine.
