# D470: Crossing to another world is a hand-off under a cover, with a return stack

Area: Engine and code · Owner: Tech · By: Agent · Status: Leaning

A door or portal is an entity with `Door { to, arrival }`; the server decides every crossing (D51) ([instances.md](../instances.md#the-crossing-and-the-way-back-d470)). In reach of a door the server warms the target and the client starts loading its asset set. Crossing, the server moves the character between instances by saving it out of one `World` and loading it into the other, and sends `Cross { to, spec, arrival, epoch }`. The client covers the screen with the crossing's effect (D72), holds the clock and tracks readiness with the loading screen's `Progress` (D135); leaves (keeps the record, despawns scoped roots, removes world resources and components, then drops the old asset set after taking the new one's handles); enters (inserts `WorldSpec`, modules build and spawn, the record is read back); places the body at the arrival and lifts the cover. The character carries a return stack of instance, place and facing; a door back pops it.

## Why

Unreal's seamless travel and Minecraft's dimension change both keep a short list of what persists and rebuild the rest; making the hand-off a save and a load means one code path for crossing, saving and the server, and a round trip tests all three. D72 rules out a traditional loading screen but allows the crossing to cover loading; D135's tracking already knows when a scene is ready. Keeping the old world as `Disabled` entities for an instant return is rejected for now: two worlds' GPU memory, and two sets of world resources cannot share one `World`. The return stack makes "back to where you left" independent of which door or how deep.
