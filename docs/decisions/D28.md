# D28: How the code is split

Area: Engine and code · Owner: Tech · By: Agent · Status: Decided

Anything that must be the same for every player lives in plain Rust crates that do not depend on Bevy (`terra_core`, `terra_gen`, `terra_voxel`, `terra_build`, `terra_items`, `terra_climate`, `terra_sim`; `terra_net` when networking starts). Only the applications, `terra_game`, the `terra_sandbox` test environment and `terra_iso`, the 2.5D top-down experiment (D634), use Bevy, `terra_world`, the world on screen the game stands on (D198), and the crates D407 cuts from the game, each on those under it: `terra_bases`, the base on screen, `terra_walker`, the walker layer, `terra_survival`, what a player carries, makes and needs, `terra_creatures`, creatures and fighting, `terra_folk`, the townsfolk, and `terra_building`, building play.

## Why

Fast tests with no GPU, a headless host, and Bevy's frequent releases touching one crate. The simulation crate already moved engines unchanged. `terra_iso` joined the list on 2026-11-07, when it moved out of `spike/iso` into the workspace on the developer's ask ("just throw it so that from root folder of repo i can call cargo whatever and it can run iso version too"): it is a front end on Bevy as the sandbox is, holding nothing every player must agree on; what it is to share with the game goes into the plain crates first ([docs/iso.md](../iso.md), D635).
