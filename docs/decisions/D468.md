# D468: A world instance is the unit loaded in and out, one to a Bevy World

Area: Engine and code · Owner: Tech · By: Agent · Status: Leaning

A world instance is one running copy of a world, a realm or a dungeon behind a door, all kinds the same unit, differing by field and theme, not by code ([instances.md](../instances.md#a-world-instance-d468)). It owns its spec, ground, sites and bases, creatures and fires, clock, climate and weather, sky and light, audio bed, asset set and spatial lookups; the character, camera, controls, UI, settings, data-file kinds and the network session are global. A Bevy `World` holds at most one instance: on the client the main `World`, the one being played; on the server a headless `App` per instance, ticked by an instance host on the task pool with `World::run_schedule(FixedMain)`. On the server an instance goes Cold, Warming, Active, Idle (empty, ticking for a grace), Frozen, Saved, Freed.

## Why

The developers on 2026-10-25: "when we talk about a dungeon, you could imagine you going to that world unloads the current world on the client and loads that dungeon - we need a system for that and we need it well compartmentalized." One instance to a `World` lets every module keep treating its resources as the world's, unchanged on client and server; Minecraft's dimensions are one `ServerLevel` each in one server, and WoW frees an instance after an idle timer. Separate `World`s tick in parallel without locks and are the unit a server of a thousand players can move between processes (D52). Rejected: one `World` with an instance id on every entity and resource, which would change every query and all 243 resource types and make a leak between worlds a logic bug instead of impossible. To measure first: an empty instance's tick cost times the dungeons a busy server holds; if too high, a kind can be embedded in its realm, as Valheim does, without touching modules.
