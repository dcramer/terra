# D635: The iso experiment is the game under an iso camera, a sibling game on shared crates, or kept apart

Area: The game as a whole · Owner: Design · By: — · Status: Open

There are three ways for the 2.5D top-down experiment (`spike/iso`, moving to `crates/terra_iso`) to stand with the game ([iso.md](../iso.md)):

- **A. One game with an iso camera.** Iso becomes a camera, its controls and a look over the game's own world, with one binary, one world and one server. Its biomes become realms' themes and sites.
- **B. A sibling game on shared crates.** Iso gets its own binary and authored scenes on the game's tick, intent, mover, fight rules, creatures and networking, with a world layer of its own.
- **C. Kept apart.** Iso stays an art and look lab, and only what its kit does better flows back.

Under A and B the steps are the same up to the world: input to `Intent` on the 64 Hz tick, the `terra_motion` mover, the walker split into movement and camera, the hero as a `Player`, the fight's rules, then creatures, people and animation. The agents recommend A. Open.

## Why

The developer, on making iso part of the repository's root: "make sure that they are majorly using the same systems, same networking, same ecs etc, ik lots of things will be different like models etc." Today iso shares only Bevy, the patches, the assets and `terra_core::cooked` with the game. Its hero is a point stepped each frame with no fixed tick, and its fight is a cone and a count of blows. The server decides everything (D51). Under B there is a second world layer and server to keep in step, and C does not answer the ask. Since steps 0 to 6 of iso.md are the same under A and B, the work can start before the developers choose between them. It needs only C ruled out, because under C they are not built. Which camera is D629's question, and which budgets is D630's.
