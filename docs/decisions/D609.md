# D609: A performance probe is one tool on main that measures only a settled frame

Area: Tools and workflow · Owner: Tech · By: Agent · Status: Leaning

A probe of what a change costs (a shader's variant, a pass hidden, a tunable's value) is one tool on main (an xtask task, to be built, its plugin in `terra_world::debug`), not a script each job carries in a patch. Before it reports a phase it holds the clock (`daylight.pace=0`), waits for the pipeline cache to have nothing pending and the opaque draw counts back to their most, fails a toggle that matched nothing, and prints the GPU's busy share and clocks beside its times; it runs its variants A/B/A/B in one load with an A/A pair for the noise floor. A lever being tried lands on main behind a tunable, off, with its tests passing and the default unchanged, so the next job measures it on main. A bench (D185) still decides whether a change lands. [research/2026-11-03-performance-systems.md](../../research/2026-11-03-performance-systems.md#4-proposals-ranked).

## Why

On 2026-11-02 probes misled five times, each costing a job or most of one: the ground undrawn 500 frames after a shader swap, the clock running (j11's fog gain was the sun going behind the ridge), views of sky and water that measured nothing, a toggle that matched no mesh, and the GPU's times read long while it idled at low clocks. The probe lived in each job's handoff folder, so j10's fix for the first lived only in a patch. The developer wants experiments landed on main, not kept as patches (2026-11-02, relayed by the coordinator). Leaning until the tool is built from the handoffs' `probe.rs` and scripts.
