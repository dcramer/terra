# D448: Every run writes its log to a file; a played session's log says what shared the GPU

Area: Tools and workflow · Owner: Tech · By: Agent · Status: Decided

Every run of the game writes each line its log keeps to `logs/<YYYYMMDD-HHMMSS>-<experiments>[-yard].log` beside its assets (the checkout's root, or the folder a Windows copy runs from), times in UTC, each line its time, frame, level, source and text, written unbuffered as it is said so a crash or kill still leaves it (`terra_world::log_file`, a second writer beside the record's, D399); the newest 20 of each kind are kept, so agents' scripted runs never push out a session someone played. Its first lines are the command, the machine and build (`debug`), and a `Display:` line, said again whenever it changes in play: window mode, size in physical pixels and scale, focus, present mode, the screen's rate, the frame-rate limit and the quality preset (`frame_setup`, which reads what the options set rather than the options menu, so the walker needs no line of its own, D198). `cargo xtask play` and `yard` watch tools/gpu's run files (D319) every 3 s while the game runs, then append a section naming each other GPU run, its class, command and how long it overlapped, copy the log into the checkout's `logs/` (gitignored) if it ran from a Windows copy, and print its path last.

## Why

The developers played the yard and saw the frame graph red most of the time, while an offscreen bench of the scene measured 7.3 ms; it could not be diagnosed, since the per-minute frame summary and stutter warnings went only to a terminal and nothing recorded what else used the card. The developers: "i think you should just have the appropriate capable logging or whatever. we can always look into this later". Shipped games keep a log a run and the previous runs beside it (Unreal's `Saved/Logs`); the GPU's other users are what D319 lets share it with no queue.
