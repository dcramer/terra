# D414: A ratchet's baseline is raised by a change with its why, and lowered only by the full run on main

Area: Tools and workflow · Owner: Tech · By: Agent · Status: Decided

A ratchet's baseline (the artifacts and fuzz counts, D287; the size baseline, D396) changes two ways, and a change makes only one of them. **A rise** is the change's: `cargo xtask artifacts [--quick] --raise "<why>"` or `cargo xtask fuzz --raise "<why>"` writes only the counts that rose or are new, each with that why; the size baseline never rises (D396). **A fall** is the full run on main (`cargo xtask nightly`)'s (`cargo xtask nightly`, D411): `--ratchet` passes a fall and leaves the baseline as it is, and `--lower` (artifacts, fuzz, `cargo xtask sizes --lower`) writes the lowered counts, run by that job alone.

The artifacts baseline is a folder, `crates/terra_build/examples/artifacts-baseline/<set>/<group>.tsv` (set `all`, `quick` or `fuzz`; a group as the ratchet counts it, "seed 103" in `seed-103.tsv`), its rows group, fault, count and why (`-` for the counts from before), so two changes to different groups never touch one file.

Both checks hold it (`xtask/src/baselines.rs`, a stage of each): against the base (HEAD before a commit, the merge-base with origin/main before a push), a count lowered or a row dropped fails unless `TERRA_BASELINE_JOB=1`, which only the full run on main sets; an artifacts count raised or added needs a why that is not empty, not `-` and not the old row's; a size row raised or added fails.

## Why

From the 2026-10-18 review of rework: `crates/terra_build/examples/artifacts-baseline.tsv` was touched by 46 commits since 2026-10-10, 18 of them re-records (12 on the evening of 10-14, e84cb6c9 and c954ba31 among them), and five commits skipped the hooks because main's ratchet was red (f4451fdb, ae383fc1, 63facc75, c52e8e2e, 4adcd41c). The ratchet told every agent "counts fell: lower the baseline with --record and commit it", so a lowering tested against one main landed beside another agent's change tested against the old, higher count, and main went red. `xtask/sizes-baseline.tsv` churned the same way (baad2bfb, and feature commits such as 2604c66c and f64a54c8 carrying `sizes --record`). A fall that waits for the full run on main costs nothing, as the ratchet still holds at the higher count; a rise is the change's own, so it stays with the change and says why. A file a group keeps two raises in different groups from conflicting.
