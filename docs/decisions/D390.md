# D390: Where an agent's context goes, and the nudge to wrap up

Area: Tools and workflow · Owner: Tech · By: Agent · Status: Decided

`node tools/token-stats/context.mjs` reads the transcripts `report.mjs` reads and prints, in at most 60 lines, each session's turns and peak and median context, the cache writes by likely cause (first turn, compaction, cache expired with the tool that ran across the gap, cache miss, or growth shared out among tool results, attachments, prompts and output), the largest writes, the largest tool results by tool, file, command and image, and subagents' first-turn prefixes. A PostToolUse hook (`context.mjs --hook`) reads only the transcript's tail, a subagent's own inside one, and when the last call's context passes 200k tokens, then each 100k more, adds one line once per crossing (`additionalContext`): finish the unit of work, hand off with a short summary, read by range or grep.

## Why

The token stats on 2026-10-16: output is about 4% of the cost, cache writes 48 to 77%, context averages 330 to 470k a turn, and writes per message rose sixfold in four days with nobody knowing why. At 200k a turn's read costs $0.04 and an expired hour's rewrite $1.60 on Opus 5.5, both growing with the context, against a few thousand tokens of summary for a fresh start.
