# D389: A file per decision

Area: Tools and workflow · Owner: Tech · By: Agent · Status: Decided

Each decision is its own file, `docs/decisions/Dnnn.md`: `# Dnnn: Topic`, a line `Area: … · Owner: … · By: … · Status: …`, the decision, then `## Why` and the reason. `docs/decisions.md` is their index, written by `node tools/docs/docs.ts --render` under a hand-written preamble: per area a row each, number, topic, owner, by, status and a gist, the decision's first sentence cut to 56 characters at a clause or word. The docs check fails on a file of the wrong shape or name, an index that is not its render (naming the file to edit instead), a table written into the page by hand, and a decision cited in any tracked text file that has no file. `cargo xtask decision` prints the next free number, from the files here and on origin/main; `cargo xtask decision D28 D198` prints those decisions in full, each with the log's lines that name it. Git merges the index by union, since the check catches a bad merge and `--render` mends it. Two agents taking one number at once now meet as the rebase stopping on the file both added; the second renumbers theirs. Amends D376.

## Why

The one table was 484 KB, about 120,000 tokens, read by every agent at the start of every session, and 380 of the last 654 commits touched it, so it was where rebases conflicted. The index is 61 KB, about 15,000 tokens, and a decision is read whole only when it matters to the work. The split was proved lossless by parsing the old table and the new files apart and comparing every field, links resolved to the files they name: no differences across 385 decisions. The gist's length is what keeps the index near 60 KB.
