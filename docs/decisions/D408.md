# D408: Release builds our crates incrementally; bench builds them whole

Area: Tools and workflow · Owner: Tech · By: Agent · Status: Decided

Our own crates build incrementally in the release profile, and the dependencies do not (`[profile.release]` in `Cargo.toml`), so a shot, film, look, artifacts or fuzz ratchet after an edit compiles only what the edit changed; the dependencies are as the seed builds them. `cargo xtask bench` builds the `bench` profile, a release with nothing incremental, as a player's build is: it shares the release folder and its dependencies, and keeps its own copy of our crates.

## Measured

On the 24-core machine with other agents building and rendering (load average in brackets):

| | Before | After |
|---|---|---|
| An edit to terra_build (a new function), then `cargo build --release -p terra_sandbox`, as a shot, film or look builds it | 25m 34s [65-73]; 12m 09s [33-52] | 1m 51s [65-73]; 31 s [2] |
| The first release build of our crates in a seeded worktree, dependencies linked | 7m 16s [17-33] | 19m 53s [34-100], once |
| A cold `bench` build of our crates, beside an incremental release one | | 28m 55s [65-80], once a worktree |

## Why

After D398 and D406 the developers asked for the obvious speedups left (2026-10-18). Release was not incremental, so every edit to a crate under the sandbox recompiled it and every crate above it from nothing at opt 3 before the first shot. The incremental code is a little slower, which no shot or film notices; what is timed against the budget is bench's, built whole.
